# Data Model: Privacy Tools (Spec 024)

Mechanisms are in [research.md](research.md); signatures in [contracts/PrivacyToolsContracts.kt](contracts/PrivacyToolsContracts.kt).

## Persisted

### Room v5 — `fireproof_sites` — `FireproofSiteEntity`

| Column | Type | Notes |
|---|---|---|
| `site` | TEXT, PRIMARY KEY | Registrable domain from Spec 023's `PublicSuffixMatcher`, lower-case ASCII (IDN as punycode). For an IP or single-label host, the host itself. |
| `added_at` | INTEGER NOT NULL | Epoch millis; newest first in Settings. |

- Created by `MIGRATION_4_5` (additive `CREATE TABLE`; no existing table touched). `5.json` exported and committed. No destructive fallback.
- Domain model: `FireproofSite(site: String, addedAt: Instant)`.
- Normal browsing only (FR-011): no incognito counterpart exists, in memory or on disk.

### DataStore — one key

| Key | Type | Meaning |
|---|---|---|
| `StorageKeys.FIRE_IN_PROGRESS` (`fire_in_progress`) | Boolean, default `false` | Written `true` **and awaited** before the first destructive step of a Fire run; written `false` after the last. `true` at start-up means a run was interrupted (FR-007, research R6). It is part of Auto Backup like every other setting; a `true` restored onto a new install only causes one extra Fire on an empty browser, which deletes nothing that exists. |

### `FireState`

```
sealed interface FireState {
    data object Idle
    data object Running          // overlay visible, Fire controls disabled
    data class Finished(val result: FireResult)   // overlay fades out, Home shown, then → Idle
}
```

### `FireResult`

`FireResult(failedSteps: Set<FireStep>, siteDataPath: SiteDataPath)` — never shown as an error dialog; a failed step is logged and left for the next run only when the `FIRE_IN_PROGRESS` marker is still set. `SiteDataPath` = `Complete` (no fireproof sites, Spec 016 path returned `Complete`) · `PerSite` (fireproof sites, `DELETE_BROWSING_DATA` available) · `Fallback` (fireproof sites on an older engine, **or** no fireproof sites and Spec 016's path returned `Partial`; research R3 limitation). Spec 016's `Failed` → step 5 is in `failedSteps`.

## Fire run — ordered steps

The order is load-bearing; each step runs in its own failure boundary (as `ClearBrowsingDataUseCase`), cancellation is rethrown.

| # | Step | Why here |
|---|---|---|
| 0 | `FIRE_IN_PROGRESS = true` (awaited) | Interrupted run is detectable (FR-007) |
| 1 | Collect **candidate hosts**: distinct hosts of history entries, open normal **and incognito** tabs, remembered site permissions, `WebStorage.getOrigins()` | Must precede steps 3 and 6, which erase the sources |
| 2 | Close every incognito tab through Spec 012's teardown (WebView 9-step destroy, cookie snapshot **restored**, incognito exceptions cleared) | The live cookie jar is back to its pre-incognito state, so step 5 never keeps an incognito cookie (FR-011) |
| 3 | `ScreenshotCache.clearAll()`, then `TabRepository.closeAllTabs()`, which deletes every normal tab row and leaves exactly one fresh normal tab on `thirtysix:home`, active (Spec 011); WebViews are disposed by the UI reacting to the new tab list | Old tabs can never be restored after this point (FR-007, SC-005) |
| 4 | `HistoryRepository.clearAll()` | FR-003 |
| 5 | **Cookies & site data** (research R2–R4): if no fireproof site → Spec 016's `clearCookiesAndSiteData()` (`Complete`). Otherwise: snapshot fireproof cookies → per-site delete of every non-fireproof candidate site → delete non-fireproof `WebStorage` origins → remove all cookies → restore the fireproof snapshot | FR-003, FR-010 |
| 6 | Web page cache: `clearWebCache()` unless step 5 was `Complete` | FR-003 (whole cache, spec Assumption) |
| 7 | Site permissions: remove remembered decisions whose registrable domain is not fireproof; `OneTimeGrantStore.retainOnly(fireproof)` | FR-004a |
| 8 | Favicons: `FaviconCache.retainOnly(keepHosts)` where `keepHosts` = bookmark hosts ∪ candidate hosts whose site is fireproof ∪ each fireproof site and `www.` + site | FR-008 |
| 9 | Session traces: `HttpsUpgradeFailureStore.clear()`; `PrivacyScriptSession.regenerate()` | FR-003a |
| 10 | Nothing to do: the home tab from step 3 is the only tab. Kept as a numbered checkpoint so INV-1 reads the same | FR-005 |
| 11 | `FIRE_IN_PROGRESS = false` | Run complete |

**Never touched**: bookmarks, downloads (rows, files, transfers), settings, `site_protection_exceptions`, `fireproof_sites` (FR-004, SC-004).

**Resume** (start-up with the marker `true`): run steps 1–11 again (step 3 again leaves one home tab) before any tab is shown. Every step is idempotent: on an empty state each is a no-op or re-clears nothing.

## Fireproof matching rule

`isFireproof(host) = registrableDomain(host) ∈ FireproofSiteSnapshot.value`. Applied to candidate hosts (step 5), permission origins (step 7) and favicon hosts (step 8). Same registrable-domain rule as Spec 023 exceptions, so `mail.example.com` is covered by fireproofing `example.com`.

## Script inputs (per WebView, research R5–R7)

| Input | Source | Change → |
|---|---|---|
| `sessionSecret` | `PrivacyScriptSession` | re-install on all live WebViews (only after Fire, when none survive) |
| `exceptedSites` | Spec 023 normal snapshot, or the incognito store for an incognito WebView | re-install on the affected WebViews; the per-site switch already reloads the page |
| `isSupported` | `WebViewFeature.isFeatureSupported(DOCUMENT_START_SCRIPT)` | constant per process |

The installed text is `prelude(inputs) + bundled assets`; the prelude is a JSON object literal built only from the three inputs above (no remote data, Constitution §II-1).

## Invariants

1. **INV-1** No Fire step runs before `FIRE_IN_PROGRESS` is durably `true`; the marker becomes `false` only after step 10.
2. **INV-2** Step 2 (incognito teardown) precedes step 5's fireproof cookie snapshot.
3. **INV-3** Step 1 precedes steps 3, 4 and 7.
4. **INV-4** A Fire run never deletes a row from `bookmarks`, `bookmark_folders`, `download_records`, `site_protection_exceptions` or `fireproof_sites`, and never writes a DataStore key other than `FIRE_IN_PROGRESS`.
5. **INV-5** At most one Fire run at a time (`FireCoordinator` mutex); a second trigger while `Running` is ignored.
6. **INV-6** Incognito WebViews never offer fireproofing. Incognito tab hosts are candidate hosts for **deletion** only; a fireproof site's data written during incognito is not separable and is kept with the site (documented in research R2).
7. **INV-7** The dashboard's protection switch calls Spec 023's `SetSiteProtectionUseCase`; it never writes exceptions itself.
8. **INV-8** No script is installed when `DOCUMENT_START_SCRIPT` is unsupported; no code path injects script any other way (`evaluateJavascript`, `loadUrl("javascript:")`).
9. **INV-9** Scripts never call into the app: the bundled sources contain no `postMessage` to the host app, no `prompt()`/`alert()` channel and no navigation to a custom scheme; the app registers no listener.
10. **INV-10** Clear browsing data ignores fireproofing (US2 #6) and gains the opt-in `FireproofSites` category, which empties the table.
